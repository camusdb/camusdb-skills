# CamusDB DDL syntax

Read this file before you write or review a DDL statement. It lists the forms
that the docs describe. A form that is not here is not documented. Do not use
it without a test.

Sources: https://camusdb.github.io/docs/sql-schema,
https://camusdb.github.io/docs/sql-indexes,
https://camusdb.github.io/docs/json,
https://camusdb.github.io/docs/sql-writes,
https://camusdb.github.io/docs/check-constraints,

## Databases

```sql
CREATE DATABASE IF NOT EXISTS app;
COMMENT ON DATABASE app IS 'Primary application database';
ALTER DATABASE app RENAME TO app_prod;   -- or RENAME DATABASE app TO app_prod
DROP DATABASE IF EXISTS app;             -- keeps a recoverable orphan
```

- Create a database before any table DDL. An unknown database fails with
  `CADB0010 DatabaseDoesntExist`.
- `_system` and `information_schema` are reserved (`CADB0018`).
- `CREATE DATABASE` has no inline `COMMENT`. Use `COMMENT ON DATABASE`.

## CREATE TABLE

The clause order is fixed:

```sql
CREATE TABLE [IF NOT EXISTS] name (
  column_definition [, ...]
  [, inline_constraint [, ...]]
)
[PRIMARY KEY (col [ASC|DESC] [, ...])]
[COMMENT 'table comment']
[WITH (setting = value [, ...])];
```

Column definition:

```sql
name type [NULL | NOT NULL] [PRIMARY KEY] [UNIQUE]
  [DEFAULT (expr)]
  [GENERATED ALWAYS AS IDENTITY | GENERATED BY DEFAULT AS IDENTITY]
  [CHECK (predicate)]
  [CONSTRAINT name NOT NULL]
  [REFERENCES parent [(col)] [ON DELETE action] [ON UPDATE action]]
  [STORAGE PLAIN | MAIN | EXTERNAL | EXTENDED]
  [COMMENT 'text']
```

`SERIAL` and `BIGSERIAL` replace the type: `invoice_no BIGSERIAL`.

Inline constraints inside the parentheses:

```sql
PRIMARY KEY (col [, ...])
KEY index_name (col [ASC|DESC] [, ...]) [INCLUDE (col [, ...])] [COMMENT 'text']
UNIQUE KEY index_name (col [, ...]) [INCLUDE (col [, ...])] [COMMENT 'text']
INVERTED INDEX index_name (jsonb_col) [COMMENT 'text']
CONSTRAINT name CHECK (predicate)
CHECK (predicate)
[CONSTRAINT name] FOREIGN KEY (col [, ...]) REFERENCES parent [(col [, ...])]
  [ON DELETE action] [ON UPDATE action]
```

Full example:

```sql
CREATE TABLE orders (
  id UUID PRIMARY KEY NOT NULL DEFAULT (gen_uuid_v4()) COMMENT 'Order key',
  customer_id UUID NOT NULL COMMENT 'Owner of the order',
  order_no INT64 GENERATED BY DEFAULT AS IDENTITY COMMENT 'Printed number',
  status STRING(16) NOT NULL DEFAULT ('pending'),
  total NUMERIC NOT NULL CHECK (total >= 0),
  notes STRING STORAGE EXTENDED,
  created_at DATETIME NOT NULL DEFAULT (now()),
  CONSTRAINT orders_valid_status CHECK (status IN ('pending', 'paid', 'shipped')),
  CONSTRAINT orders_customer_fk FOREIGN KEY (customer_id) REFERENCES customers (id),
  KEY orders_customer_idx (customer_id, created_at DESC) INCLUDE (status, total)
) COMMENT 'Customer orders';
```

Rules:

- A primary key is mandatory (`CADB0400`).
- Primary key columns are always `NOT NULL`.
- Use `KEY` or `UNIQUE KEY` for an inline index. The docs show no inline
  `INDEX name (...)` form.
- For a multi-column unique rule, use `UNIQUE KEY name (a, b)` or
  `CREATE UNIQUE INDEX`. The docs show no `CONSTRAINT name UNIQUE (a, b)` form.
- A named check must be a table-level `CONSTRAINT name CHECK (...)`. A named
  column-level check is not supported.
- A column-level check can reference other columns of the same row.
- Names keep their case, but lookups ignore case. Two names that differ only
  in case are rejected.
- Quote an identifier with backticks. Double quotes make a string literal.

### CREATE TABLE AS SELECT

```sql
CREATE TABLE vintage_robots AS SELECT name, year FROM robots WHERE year < 1990;
CREATE TABLE empty_copy AS SELECT * FROM robots WITH NO DATA;
```

CTAS adds its own generated primary key column. It copies no index,
constraint, default, comment, setting, or foreign key. Add them afterwards.

## Defaults

```sql
DEFAULT (0)
DEFAULT ('pending')
DEFAULT (gen_id())          -- OID
DEFAULT (gen_uuid_v4())     -- UUID / GUID
DEFAULT (gen_uuid_v7())     -- UUID / GUID
DEFAULT (nextval('seq'))    -- INT64
DEFAULT (now())             -- DATETIME
```

A function default must be a bare call with no argument. A type mismatch is
rejected.

## Column storage strategies

| Strategy | Compresses | Out of line | Use for |
| --- | --- | --- | --- |
| `EXTENDED` (default) | Yes | At or above 2048 bytes | Text, JSON, documents |
| `MAIN` | Yes | Never | Compressible values most queries read |
| `EXTERNAL` | Never | At or above 2048 bytes | Images, archives, incompressible blobs |
| `PLAIN` | Never | Never | Values every query reads, such as embeddings |

- Only `STRING`, `BYTES`/`BLOB`, `JSONB`, and `ARRAY` columns take a strategy.
  Others fail with `CADB0414 ColumnStorageNotApplicable`.
- Compression (LZ4) is tried at 256 bytes and kept at 12 percent saving.
- Compression runs before the out-of-line decision.

```sql
ALTER TABLE docs ALTER COLUMN image SET STORAGE EXTERNAL;
ALTER TABLE docs REWRITE STORAGE;          -- convert existing rows
ALTER TABLE docs REWRITE STORAGE INLINE;   -- back to inline, uncompressed
```

`SET STORAGE` affects future writes only. A rewrite runs in batches of
`large_value_rewrite_batch_rows` (200), is resumable, and can make concurrent
writers retry with `CADB0502`. Run it in a quiet period.

## Indexes

```sql
CREATE [UNIQUE] INDEX name ON table (col [ASC|DESC] [, ...]) [INCLUDE (col [, ...])];

ALTER TABLE t ADD INDEX name (col [ASC|DESC] [, ...]) [INCLUDE (...)];
ALTER TABLE t ADD UNIQUE INDEX name (col [, ...]) [INCLUDE (...)];
ALTER TABLE t RENAME INDEX old_name TO new_name;
COMMENT ON INDEX t.name IS 'text';

DROP INDEX [IF EXISTS] name ON t;
DROP INDEX [IF EXISTS] t.name;
ALTER TABLE t DROP INDEX [IF EXISTS] name;
```

- The three `DROP INDEX` forms are one statement with the same rules.
- A bare `DROP INDEX name` fails with `InvalidInput`. Index names are unique per
  table, not per database. `DROP INDEX db.t.name` also fails.
- A quoted table name that contains a dot cannot use `DROP INDEX t.name`. Use
  `DROP INDEX name ON t`.
- `IF EXISTS` hides a missing table or index only. A foreign key that needs the
  index still fails with `DependentObjectsExist` (`CADB0530`).
- `DROP INDEX` cannot reach the primary key. Use `ALTER TABLE t DROP PRIMARY KEY`.
- `DROP INDEX` needs the `INDEX` privilege on the table.
- `ASC` is the default direction.
- `DESC` works on `OID`, `UUID`, `INT64`, `FLOAT64`, `FLOAT32`, `BOOL`, `DATE`,
  and `DATETIME`. `DESC` on `STRING` or `BYTES` fails with `InvalidInput`.
- `ARRAY(T)` cannot be an index key. It can be an `INCLUDE` column.
- An index spans at most 32 columns, key plus `INCLUDE`.
- The `INCLUDE` payload is at most 4 KiB per entry.
- An `INCLUDE` column cannot repeat a key column and takes no direction.
- A primary key takes no `INCLUDE`.
- `UNIQUE` applies to the key columns only.
- To change `INCLUDE`, drop the index and create it again.
- Renaming to an existing name, or renaming a missing index, fails with
  `InvalidInput`.
- `SHOW INDEXES FROM t` lists the indexes, including owned `~fk_` indexes.
- `SHOW INDEX USAGE FROM t` shows the reads and writes of each index. An index
  is a candidate to drop when `reads` and `constraint_reads` are 0 over a long
  window, and `writes` is not 0.

### GIN indexes

A GIN index maps each part of a `JSONB` document to the rows that hold it.

```sql
CREATE INDEX events_payload_gin ON events USING GIN (payload);
CREATE INDEX events_payload_gin ON events USING GIN (payload jsonb_path_ops);
CREATE INVERTED INDEX events_payload_gin ON events (payload);

CREATE TABLE events (
  id INT64 PRIMARY KEY,
  payload JSONB,
  INVERTED INDEX events_payload_gin (payload)
);
```

- A GIN index has exactly one column, and that column must be `JSONB`. It has no
  `INCLUDE` and no `DESC`. Other shapes fail with `InvalidInput`.
- `jsonb_ops` and `jsonb_path_ops` build the same index.
- `SHOW INDEXES` shows `Index_type` `GIN`. `SHOW CREATE TABLE` shows the inline
  `INVERTED INDEX` form.
- `CREATE INDEX` over an existing table backfills while writes continue.

The planner uses a GIN index for a top-level `WHERE` conjunct when the other
operand is a constant:

| Conjunct | Notes |
| --- | --- |
| `col @> doc`, `doc <@ col` | Containment |
| `col ? key`, `col ?\| keys`, `col ?& keys` | Key or string element |
| `col ->> 'k' = text` | Not when `text` starts with `{` or `[` |
| `col -> 'k' = doc` | Same as `col @> {"k": doc}` |

The index is not used for a conjunct under `OR` or `NOT`, `col <@ doc`,
`col @> '{}'`, `col @> '[]'`, `col @> <scalar>`, or a join.

Costs:

- An `INSERT` writes one entry for each distinct leaf of the document. Each
  entry counts against the mutation limit. Over the limit, the statement fails
  with `CADB0506`. The index never leaves entries out.
- An `UPDATE` writes only the entries that changed. A `NULL` document has none.
- Under Serializable, a GIN scan takes a range lock over each entry range it
  reads. A key that every document holds gives a large range, which blocks more
  writers.

### Unique indexes as conflict arbiters

`INSERT ... ON CONFLICT` and `UPSERT` depend on unique indexes:

- `ON CONFLICT (a, b)` needs a unique index on exactly the columns `{a, b}`. The
  order does not matter. No match fails with `InvalidInput`.
- `ON CONFLICT ON CONSTRAINT name` names a unique index. The primary key answers
  to `<table>_pkey`.
- `UPSERT` uses the primary key.
- A `NULL` in the arbiter key never conflicts. The row is always inserted.
- A duplicate on a unique index that is not an arbiter still fails with
  `DuplicateUniqueKeyValue`.
- A unique index still being built cannot be the arbiter.

Add the unique index that the upsert needs. MySQL `ON DUPLICATE KEY UPDATE` and
`MERGE` are not supported.

## ALTER TABLE: columns

```sql
ALTER TABLE t ADD COLUMN c STRING NULL;
ALTER TABLE t ADD COLUMN c STRING NULL COMMENT 'Operator notes';
ALTER TABLE t ADD COLUMN c INT64 NOT NULL DEFAULT (0);
ALTER TABLE t ADD COLUMN doc JSONB NULL;
ALTER TABLE t DROP COLUMN c;
ALTER TABLE t RENAME COLUMN old_name TO new_name;
ALTER TABLE t ALTER COLUMN c SET NOT NULL;
ALTER TABLE t ALTER COLUMN c DROP NOT NULL;
ALTER TABLE t RENAME TO new_table_name;
```

- `ADD COLUMN ... NOT NULL` with no `DEFAULT` fails with `CADB0301` when the
  table has rows.
- `DROP COLUMN` fails when an index uses the column, as a key or `INCLUDE`
  column. Drop the index first.
- `DROP COLUMN` of a column in a foreign key fails with `CADB0530`.
- `SET NOT NULL` scans the table. It fails with `CADB0301` on an existing `NULL`.
- You cannot drop `NOT NULL` from a primary key column.
- A rename moves no data. A rename to an existing name fails with
  `TableAlreadyExists` or `DuplicateColumn`.
- The docs describe no statement that changes a column type.

## ALTER TABLE: primary key and constraints

```sql
ALTER TABLE t ADD PRIMARY KEY (id);
ALTER TABLE t DROP PRIMARY KEY;

ALTER TABLE t ADD CONSTRAINT positive_price CHECK (price > 0);
ALTER TABLE t ADD CONSTRAINT t_city_fk FOREIGN KEY (city) REFERENCES cities (name);
ALTER TABLE t DROP CONSTRAINT positive_price;
ALTER TABLE t DROP CONSTRAINT employees_name_not_null;
```

- `ADD CONSTRAINT ... CHECK` scans existing rows. A violating row fails the
  statement with `CADB0303`. The check is enforced before the scan starts.
- `ADD CONSTRAINT ... FOREIGN KEY` validates existing child rows. An orphan
  fails it with `CADB0304`. Quiesce child writers, or run an orphan check after.
- `CHECK`, named `NOT NULL`, and `FOREIGN KEY` share one name space per table.

Generated constraint names:

| Definition | Name |
| --- | --- |
| `price FLOAT64 CHECK (price > 0)` on `products` | `products_price_check` |
| Unnamed table-level `CHECK (...)` | `products_checkN` |
| `SET NOT NULL` without a name | `{table}_{column}_not_null` |
| Unnamed foreign key on `weather.city` | `weather_city_fkey` |

## CHECK predicates

Allowed: comparisons, `AND`/`OR`/`NOT`, arithmetic, `BETWEEN`, `LIKE`, `ILIKE`,
`~`, `~*`, `!~`, `!~*`, `IS [NOT] NULL`, `IN` with literals, `CASE ... END`,
deterministic scalar functions, `CAST`, and array subscripts.

Rejected with `CADB0400`: a subquery, an aggregate, a volatile function
(`now()`, `gen_id()`, `gen_uuid_v4()`, `gen_uuid_v7()`), an unknown column, and
a malformed literal regex pattern.

A check whose result is `NULL` passes. Combine it with `NOT NULL`.

A comparison between types with no rule, such as a `STRING` column and a number,
rejects the row at write time with `CADB0303`. Write a `CAST`. See
[data-types.md](data-types.md#comparing-different-types).

## Foreign keys

| Form | Result |
| --- | --- |
| Column `REFERENCES parent [(col)]` | Accepted |
| Table `FOREIGN KEY (...) REFERENCES parent (...)` | Accepted |
| Composite keys, self-reference | Accepted |
| `ON DELETE`/`ON UPDATE` `NO ACTION` (default) or `RESTRICT` | Accepted |
| `MATCH SIMPLE` (default) | Accepted |
| `CASCADE`, `SET NULL`, `SET DEFAULT` | `CADB0533` |
| `MATCH FULL`, `MATCH PARTIAL` | `CADB0533` |
| `DEFERRABLE`, `INITIALLY DEFERRED` | `CADB0533` |
| A cycle across two or more tables | `CADB0416` |
| Parent in another database, a source branch, or a view | `CADB0415` |
| Parent table with row-level TTL | `CADB0533` |

- The referenced columns must be exactly the parent primary key columns, or
  exactly the columns of a public unique index. Order can differ.
- Paired columns must have the same type. `STRING(N)` lengths can differ.
- A `JSONB` column cannot be part of a foreign key.
- Omit the parent column list to reference the parent primary key.
- Creating a foreign key needs `SELECT` on the parent. There is no
  `REFERENCES` privilege.
- `DROP TABLE` or `TRUNCATE` of a referenced parent fails with `CADB0530`.
- An owned `~fk_` index cannot be dropped directly. Drop the constraint.

## Sequences and identity

```sql
CREATE SEQUENCE [IF NOT EXISTS] order_no
  START WITH 1000 INCREMENT BY 1 MINVALUE 1000 MAXVALUE 999999 CACHE 1;

ALTER SEQUENCE order_no RESTART WITH 500;
ALTER SEQUENCE order_no INCREMENT BY 10;
ALTER SEQUENCE order_no NO MAXVALUE;
ALTER SEQUENCE order_no RENAME TO order_number;
DROP SEQUENCE order_number;
COMMENT ON SEQUENCE order_no IS 'One per customer order';
SHOW SEQUENCES LIKE 'order%';
SHOW CREATE SEQUENCE order_no;
```

| Option | Default |
| --- | --- |
| `START [WITH] n` | `MINVALUE` |
| `INCREMENT [BY] n` | `1`; must be positive |
| `MINVALUE n` / `NO MINVALUE` | `1` |
| `MAXVALUE n` / `NO MAXVALUE` | none |
| `CACHE n` | `1` |
| `NO CYCLE` | The only cycle behavior. `CYCLE` is not supported. |

- A sequence shares the name space of tables and views (`CADB0542`).
- `nextval` works in `INSERT ... VALUES`, in column defaults used by `INSERT`,
  and in a `SELECT` without `FROM`. Elsewhere it fails with `CADB0547`.
- An identity sequence is owned by its column. `DROP SEQUENCE` on it fails
  with `CADB0548`.
- `TRUNCATE ... RESTART IDENTITY` restarts owned sequences only.
- `ALTER SEQUENCE ... RESTART` cannot run in an explicit transaction.
- Values have gaps and are not a strict insert order.

## Table settings and row-level TTL

```sql
CREATE TABLE sessions (...) WITH (ttl_expiration_expression = 'expires_at');

ALTER TABLE sessions SET (ttl_expiration_expression = 'expires_at', ttl_job_cron = '@hourly');
ALTER TABLE sessions SET (ttl_pause = 'true');
ALTER TABLE sessions RESET (ttl_job_cron);
ALTER TABLE sessions RESET (ttl);
ALTER TABLE logs SET (sql_stats_automatic_collection_enabled = false);
```

| Parameter | Default | Notes |
| --- | --- | --- |
| `ttl_expiration_expression` | none | A bare column name. Enables TTL. |
| `ttl_pause` | `false` | Stops the sweep and keeps the settings. |
| `ttl_job_cron` | `'@daily'` | `@hourly`, `@daily`, `@weekly`, `@monthly`, `@midnight` only. |
| `ttl_select_batch_size` | `500` | Rows per scan batch. |
| `ttl_delete_batch_size` | `100` | Rows per delete transaction. |
| `ttl_select_rate_limit` | `0` | Rows per second; `0` is no limit. |
| `ttl_delete_rate_limit` | `100` | Rows per second; `0` is no limit. |
| `ttl_grace_ms` | `0` | For clock skew only. Not a retention rule. |

- The expiry column is `DATETIME`, `DATE`, or `INT64` epoch milliseconds.
- A `NULL` expiry never expires.
- `RESET (ttl)` clears every TTL parameter.
- Not supported: an SQL expression as the expiry, a five-field cron string,
  `ttl_expire_after`, `ttl_disable_changefeed_replication`,
  `ttl_row_stats_poll_interval`, and `ttl_label_metrics`.
- A setting name is not case-sensitive. An unknown name is rejected.

## Comments

```sql
COMMENT ON TABLE users IS 'Application users';
COMMENT ON COLUMN users.email IS 'Unique login email address';
COMMENT ON INDEX users.email_idx IS 'Lookup by login email';
COMMENT ON COLUMN users.email IS NULL;   -- removes the comment
```

- Qualify a column or an index with its table.
- The limit is 65,535 characters (`CADB0511`).
- The clause is `COMMENT 'text'`, with no `=`.
- No `COMMENT ON` exists for a primary key index, a constraint, a branch, or a
  function.

## Drop and recover

```sql
DROP TABLE IF EXISTS robots;     -- keeps a recoverable orphan
SHOW ORPHAN TABLES;
CREATE TABLE robots_recovered RELINK TO "A0";
DROP TABLE robots FORCE;         -- permanent, no recovery
TRUNCATE TABLE orders RESTART IDENTITY;
```

A table recovered with `RELINK TO` comes back without its foreign keys. Add
them again with `ALTER TABLE ... ADD CONSTRAINT`.

## Inspect

```sql
SHOW CREATE TABLE orders;
SHOW CREATE TABLE orders WITHOUT INDEXES;
SHOW INDEXES FROM orders;
SHOW INDEX USAGE FROM orders;
SHOW RANGES FROM TABLE orders;
SHOW RANGES FROM INDEX orders@orders_customer_idx;
```

`SHOW CREATE TABLE` output can be run again. It omits owned `~fk_` indexes.
